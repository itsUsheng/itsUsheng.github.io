今天做了一件很具体的事：把同一段视频分别交给 DeepSeekHarness 和 Kimi K3.1 Pro 做 caption 标注，然后拿人工标准稿逐字逐句对照。结果不是“谁好谁坏”这么简单，而是暴露了一条完整的因果链——输入管线决定证据形态，证据形态决定幻觉类型，幻觉类型决定人工该往哪里看。

这篇博客把今天的讨论整理成一套可复用的思路：为什么同一视频会产出不同 caption、AI 在视频 caption 上系统性薄弱在哪里、如何自己写 prompt 降低重复率并修正错误、以及后续选择 caption 辅助工具时应该看什么。

一、现象：“它们看到的视频不一样”。

Kimi K3.1 Pro 在常见接入方式中并不原生支持视频输入，视频往往被抽成关键帧图片序列再送进模型。它“看到”的是离散的静态画面集合，而不是连续视频流。DeepSeekHarness 则是一个插件框架，视频理解通过 dsh-video-understanding 这类插件完成：视觉描述可能来自 VideoChat3/Qwen3-VL，语音转写由 Whisper 独立处理，关键帧由 ffmpeg 抽取，最后再由决策模型综合多路证据生成 caption。

Kimi 的 caption 本质上是“基于图片序列的推断”，DeepSeekHarness 的 caption 本质上是“多源转述后的综合”。两者在信息获取的起点上就已经分道扬镳。底层视觉模型不同、解码随机性不同、提示词模板不同，只是在此基础上进一步放大了分歧。

二、案例：逐字对照后，错误不是随机的
用一段《兰戈》追逐戏的人工标准稿做基准。

DeepSeek 的输出问题更重：它把主体映射整体搞错——“主体1=豆豆、主体2=地鼠、主体3=兰戈”，导致“谁给谁缰绳、谁打谁、谁道歉”全篇错位。它写“地鼠把皮缰绳塞给豆豆”，方向反了；把“豆豆出左拳打地鼠”改成“地鼠按住豆豆肩膀、另一骑手钳住豆豆手臂”...局部细节很丰富，但大量是细节丰富的错配。

Kimi 的主体表基本正确，开场大全景、缰绳方向、部分字幕优于 DeepSeek。但核心事件归属错得更隐蔽：它把“地鼠与豆豆扭打、地鼠拉豆豆肩臂”写成“兰戈从篷布翻落在豆豆身旁，双手抓住豆豆手臂和肩膀”还共同遗漏了第3秒打斗、第11秒撞石头、第16–17秒过肩镜头与后方骑走鹃地鼠追击、第19秒误打左脸等关键事件。

结论很清晰：两份都不能通过逐字评测。

DeepSeek 是主体映射层面的系统性崩坏，修正成本更高；Kimi 是框架正确但事件归属和关键动作链错配，错误更隐蔽。 这也说明，caption 评测不能只看“像不像”，而要拆成主体一致性、事件归属、时序因果、覆盖完整性、字幕逐字准确性等维度。

三、AI 在视频 caption 上的系统性薄弱环节
这些错误不是偶然的，它们对应几类稳定的失败模式。

第一，幻觉在自由生成中被放大。 Video-LLM 在开放 caption 中比在选择题验证中更容易编造“看起来合理”但视觉无根据的内容。对象/属性幻觉、动作幻觉、先验驱动的时序幻觉都很常见。比如视频里苹果被向上抛，模型可能依据“苹果会从树上落下”的先验，幻觉出下落场景。

第二，时序与因果是层级瓶颈。 模型在信息聚合、时序建模、复杂推理上的表现依次递减，低层时序错误会向上传播。顺序混淆、短暂动作遗漏、因果误判、状态变化方向错误，都是高频问题。

第三，计数是“读出失败”。 模型可能“看见”了物体，却无法把逐窗口的在场信号聚合为全局计数。所以 caption 里出现数字时，默认应视为未经核实。

第四，空间关系与细粒度运动容易被静态线索压制。 模型倾向于根据画面里的物体去“推断”最可能发生的动作，而不是真正观察运动轨迹。左右颠倒、相对位置错误、运动方向错误、快速动作遗漏，都源于此。

第五，遗漏与幻觉共生。 一段看起来“干净”但信息稀薄的 caption，可能恰恰是模型在回避感知不确定性。所以人工核查不仅要问“说错了什么”，还要问“漏掉了什么关键信息”。

这些薄弱环节给了一张“锚点地图”：人工精力应优先投向时序关系、任何计数、细粒度运动与空间关系、听起来很顺但符合常识脚本的断言、以及覆盖完整性。

四、Kimi 的“图片底层”到底带来了什么
“以图片为底层处理视频”是一把双刃剑，不是简单的“幻觉弱”。

好处是：帧序列切断了连续时间流，限制了“叙事性幻觉”的雪球式传播。每帧相对独立解读，一个帧的错误不容易传染给其他帧。所以 Kimi 不太会编造一个完全虚构的连贯错误故事——它在架构上就缺乏进行连贯叙事的能力。

坏处是：它制造了系统性的“时序与动态幻觉”。模型被迫像看幻灯片一样处理视频，视觉编码器擅长物体、布局等空间特征，对运动、因果、先后顺序等时间特征基本“失明”。于是它容易根据静态线索推断动作，也容易让常识脚本覆盖真实观察。抽帧还会系统性丢失短暂但关键的动态信息，造成遗漏。

Kimi 用抑制“叙事性幻觉”的能力，换来了系统性的“时序与动态幻觉”缺陷。 它在静态事实核查上可能稳定，但在“发生了什么、怎么发生的、为什么发生”上不可靠。

五、为什么 DeepSeekHarness“搭载了视频阅读软件”反而幻觉更严重
这是今天最反直觉的一点。答案在于：插件架构本身可能是幻觉放大器，而不是抑制器。

DeepSeekHarness 的视频理解不是端到端原生视频流，而是通过多插件转述：抽帧、ASR、外部视觉 API、决策模型综合。每一个环节都可能引入偏差，而偏差一旦进入上下文，就会被 Agent 当作“事实”吸收并放大。插件越多，工具选择空间越大，注意力越被稀释，模型真正用于分析视觉证据的 token 占比反而下降。

更关键的是，抽帧在源头就制造了“证据真空”。连续时间流被切碎，运动、因果、先后顺序大量流失。模型面对被掏空时序信息的证据，并不会承认“我不知道”，而是用语言模型内部的常识脚本去填补。幻觉，本质上是在视觉证据不足时，语言先验对视觉判断的接管。 当 ASR 文本又比较流畅时，文本信号可能压倒稀疏的视觉信号，模型会沿着语言线索“编故事”，而不是费力核对不连贯的静态画面。这就是“懒惰解码器效应”的管线级版本。

所以选择 caption 工具时，不要只问“支不支持视频”，要问：它如何把视频变成模型能消化的证据？这个转换过程在哪里系统性地制造盲区？

六、自主写 Prompt：从一句指令升级为操作系统
如果不想完全依赖标管给的 prompt，可以把自己的 prompt 设计成三层。

第一层，先定义“必须写什么”。 用五维关键点清单锚定底线：静态实体（环境、人物、物体属性与空间配置）、动态动作与交互、听觉元素（对话逐字、音效、音乐及其与画面的关联）、时空与运镜（场景转换、时间推进、镜头运动）、跨模态叙事逻辑（听觉与视觉如何互相解释或引导）。Prompt 应直接内化这张清单，要求 AI 逐一覆盖，而不是指望它自己领会。

第二层，生成与精炼分离。 不要在一个 prompt 里同时要求“完整”和“不重复”。生成层先求“有”，容忍冗余；精炼层专门去重。去重最有效的规则是“描述一次，永不再述”：场景只在开头建立一次；人物外貌首次出现时描述，之后只用姓名或代词；环境音首次出现时注明，仅在真正变化时再提；每句对话只保留首次出现。把输入的分段描述去重，改写成带时间戳的单一连贯叙事。

第三层，错误分类修正。 发现理解错误时，不要笼统说“全改”。先分类：misinformation、hallucination、missing information、temporal error、spatial error、attribution error。然后只修改与错误直接相关的内容，保持其他已正确部分不变。你口述的反馈应该具体到“第15秒时序错误：caption 说先拿杯子再转身，但视频是先转身再拿杯子”，再让诊断 prompt 判断这是 prompt 缺口还是系统局限。前者改 prompt 文本，后者调管线结构。

可以把它固化成三个文件：checklist.md 定义底线；generate.prompt 负责初稿；refine.prompt 负责去重和分类修正。标管的 prompt 不必抛弃，而是作为基线，用你的 checklist 审计它是否覆盖底线维度，用 refine.prompt 弥补它在重复控制和错误修正上的不足。

七、还有哪些 caption 标注 AI：五条底层路线
目前可用于 caption 标注的 AI，大体沿五条路线展开。

路线一：原生音视频联合建模。 代表有 Qwen3.5-Omni/Qwen3.8-Omni-Flash、video-SALMONN 2、MiniCPM-o 4.5、Gemini 原生视频模式。输入是在时间轴上对齐的音视频 token 序列，时序保真度最高，适合动作因果、音画同步、时间戳准确性要求高的任务。风险是“集成幻觉”：模型可能只是弱耦合地并置音视频信息，产出信息丰富但关系贫乏的 caption；语音中心偏差还会弱化非语音声音。

路线二：专用微调模型。 代表有 SkyCaptioner-V1、TimeChat-Captioner。用高质量 caption 数据对基座模型定向微调，在景别、角度、运镜等结构化字段上可大幅超越基座。适合生成结构化字段，但泛化边界窄，偏离训练分布后表现会下降。

路线三：显式跨模态事件绑定。 代表有 AVSCap、SynAV。针对“集成幻觉”，在架构和训练目标上强制音视频证据绑定，直接瞄准主体错配和因果缺失。但多处于研究阶段，工程化部署不如路线一成熟。

路线四：级联管线。 代表是 Whisper 前置 ASR + 任意 LLM/VLM、CAST 等。透明度最高，错误可定位到具体环节。适合对话密集、语音主导的视频。但级联误差会累积，融合环节本身是新的幻觉源，不要期望它可靠捕捉非语音声音或音画因果。

路线五：标注平台的人机协同层。 代表有 Label Studio 集成预标注、VideoCaptioner、Chord 等。不追求端到端自动 caption，而是把 AI 当预标注器，导入标注界面由人工修正。这不是模型选择，而是工作流选择。

选型时问三个问题：你的瓶颈是“覆盖”还是“保真”？你的标注规范是“结构化字段”还是“自由叙事”？你愿意把多少判断权交给管线、多少留给自己？最务实的结构往往是：用路线一或路线二生成初稿，导入标注平台，用人工锚点做定向修正。

八、落地：一条可直接套用的提质增效工作流
评价标准前置。 先用五维清单定义“合格 caption”，再选模型。没有标准，任何输出都只是随机版本之一。

生成与评判分离。 让一个模型生成初稿，用不同家族的 LLM 做对照校验，问“caption 中声称的事件 X 在视频中是否确实发生”，而不是让它打模糊分。

人工只锚定 AI 的系统性薄弱区。 重点查时序关系、任何计数、左右方位与相对位置、快速动作、听起来很顺的常识断言、以及覆盖完整性。不要通篇重写。

错误先分类再修正。 用 temporal/spatial/attribution/missing/hallucination 分类，判断改 prompt 还是改管线。

保留少量人工种子样本。 用你亲自修正过的样本校准自动管线，定期检验输出漂移。

工具选择看证据链，不看排行榜。 管线是否引入额外转述环节、时序证据在输入中是否被保留，比模型名次更有判断价值。

结语
同一段视频产出两种 caption，不是简单的“模型强弱”问题，而是系统架构差异的必然结果。Kimi 的帧序列处理抑制了叙事性幻觉，却制造了时序与动态幻觉；DeepSeekHarness 的多插件转述管线提供了更丰富的证据来源，却也可能在证据真空处让语言先验接管，放大主体错配和因果缺失。

对 caption 标注而言，真正的提质增效不在于找到一个“没有幻觉的模型”，而在于建立一条幻觉可以被定位、被分类、被定向修正的管线：标准前置、生成与精炼分离、人工锚点精准投放、错误分类修正、工具按证据链选型。把有限的人工判断力集中在 AI 最不可靠的环节，比追逐“更强的模型”更稳定地带来质量提升。
